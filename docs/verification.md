# 3층 원정 검증 결과

검증일: 2026년 10월 4일. Godot 4.7.2 일반판, Windows, Compatibility 렌더러.

## 0.3.0 화면 개선 검증

- 6,527개 전투 규칙 검사를 다시 실행해 통과했다. 같은 시드의 자동 플레이 결과와 완료 수는 변경 전과 동일했다.
- 450×900 마우스와 360×640 터치에서 6전투 전체 진행, 상점 탭 전환, 스킬·장비 선택, 보상, 휴식, 재시작을 확인했다.
- 전장과 행동 버튼이 세로 스크롤 없이 화면 안에 들어오는지 검사했다.
- 별도 연출 검사에서 실제 공격자·대상, 전체 공격 3인, 방어막 흡수, 치유, 마지막 타격 후 보상 전환을 확인했다.
- 연출 중 전장 노드가 유지되고, 끝나면 조작이 복구되는지 확인했다.
- 손패 터치 드래그로 가로 스크롤이 움직이고 카드 선택이 발생하지 않는지 확인했다. 데스크톱 마우스 드래그는 [Godot 터치 에뮬레이션](https://docs.godotengine.org/en/stable/classes/class_scrollcontainer.html)을 사용한다.
- 캡처·로그: .qa/visual-upgrade/. 연출 캡처: .qa/visual-upgrade/feedback/.

## 자동 플레이

check_battle.gd는 6,527개 조건을 검사해 실패 0개였다. 총 660개 원정을 실행했다.

- 기본 파티, 일반 경로, 장비·스킬·회복을 선택하는 고정 정책: 119/120 완료.
- 동일 정책을 동일 시드로 반복한 120회: 파티 상태와 기록이 전부 일치.
- 기본 공격 위주로 장비·스킬 획득과 상점 구매를 생략하는 비교 정책: 0/120 완료.
- 위험 경로 고정 선택: 83/120 완료.
- 동료 조합 6종 × 시드 30개: 180회 실행, 각 조합에서 28~30회 완료.
- 기본 파티 시드 120개에서 서로 다른 최종 스킬 구성 120개를 확인했다.

이는 고정된 테스트 정책의 결과다. 실제 플레이어 승률이나 밸런스 완성도를 뜻하지 않는다. 정책은 tests/play_policy.gd에 있다.

check_ui.gd는 헤드리스, 450×900 마우스, 360×640 터치 입력에서 실패가 없었다. 희귀 이벤트는 모델 상태를 준비한 뒤 UI를 검사했다. 확인창의 확인/취소는 신호를 호출했고, 나머지 버튼 흐름은 입력 이벤트로 검사했다. 캡처에서 전투·보상·휴식·캐릭터 상세·장비 수령 화면을 확인했다.

## 배포와 한계

- Windows: exports/taptop-three-floors.exe.
- Android: exports/taptop-three-floors.apk. 버전 0.3.0, 버전 코드 3, 패키지 com.taptop.firstbattle.
- Android ABI: arm64-v8a, x86_64. 최소 SDK 24, 대상 SDK 36.
- 내보내기 초기에 Java SDK 경로 누락을 확인하고 설치된 JDK 17 경로를 지정해 해결했다.
- 설치된 Android 빌드 도구 35.0.1을 사용한다는 안내가 출력됐다. 내보내기와 서명 검증은 완료됐다.
- 0.3.0은 .tools/export-visual-upgrade 복사본에서 배포했다. 게임 스크립트 해시가 현재 소스와 일치한다. MCP 애드온과 테스트는 배포 파일에서 제외했다.
- 개발 UI 전체 진행은 검증했다. Windows 배포 EXE에서는 시작과 렌더러 초기화를 검사했다.
- Android 연결 기기가 없었다. 휴대폰 설치, 실기기 터치·화면 안전 영역·성능·백그라운드 복귀는 아직 검증하지 않았다.
- 저장·불러오기는 구현 범위에 포함하지 않는다.

검사 로그와 화면: .qa/three-floors/. Android·Windows 내보내기 로그와 배포 EXE 시작 로그도 같은 폴더에 있다. 이전 첫 전투 산출물은 별도 파일로 유지했다.
